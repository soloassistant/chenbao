## 1. 产品概述

### 1.1 一句话定位

> 边界：我们不是通用 AI 助手，也不是比价工具。价值锚只有三个——**我的数据、写回日程、按时送达**。
> 通用问答打不过免费大模型；商品历史价打不过专业比价站。这两条不做正面竞争。

把用户散落在微信里的消息、截图、文章，整理成**日程、待办、收藏**，并以**每日晨报**的形式主动呈现；再往前一步，回答「周末去哪」这类计划性问题，并把结论直接写回日程。

### 1.2 目标用户

- **信息过载的微信重度用户**：会议、约定、快递、账单散在群聊里，靠记忆管理。
- **收藏夹吃灰人群**：存了很多，从不回看。
- **需要计划但不想做攻略的人**：周末/假期出行，要结论、要预算、要能落地的行程。
- **愿意为省心付费的个人用户**：不为功能付费，为「不用自己想」付费。

### 1.3 核心价值

1. **粘贴即整理**：文字/截图 → 结构化日程与待办，冲突给候选时段。
2. **晨报主动送达**：今日日程 + 待办 + 收藏精选 + 天气 + 资讯，一屏看完。
   > 现状：H5 无推送通道，「送达」目前等于「用户主动打开」。v3.2 用日历 ICS 订阅/邮件补上（见 §4.9 F90）。
3. **真实数据**：所有用户可见数据来自真实录入或真实聚合；降级必须标注，禁止编造。
4. **一处收口**：同类能力只有一个入口、一套口径（AI 对话、热点取数、同步、额度）。

### 1.4 商业模式

- 免费 + 订阅，早鸟锁价。
- 免费档：AI 对话 **20 次/天**、语音 20 条/月（**H5 端无录音能力，该权益不可用**，仅小程序端可用）、收藏 50 条、RSS 原始资讯。
- 订阅档：语音不限次、收藏无限、AI 精选、主题与增值能力。
- 价格（元）：早鸟月付 **6.9**、标准月付 **9.9**、年付 **88**。
- **H5 无支付通道**：会员页给常驻说明 + 促销码兑换入口，不做假支付、不扣额度。

## 2. 名词定义

| 名词 | 定义 |
|---|---|
| 晨报 | 每日个人日报：今日日程 + 待办 + 收藏精选 + 天气 + 资讯 |
| 收件箱 | 粘贴文字/截图的入口；AI 提取 → 草稿 → 勾选确认入库 |
| 情报 | 晨报内的天气与资讯；免费档为 RSS 原始条目，订阅档可 AI 精选 |
| AI 精选 | 热点页手动触发：按兴趣画像挑 ≤10 条并给理由 |
| 真实数据原则 | 用户可见数据必须可追溯；兜底必须显式标注「参考/降级」 |
| 用量真记账 | 额度按实际调用计数；展示与校验共用同一份计数 |
| 权益服务端化 | 会员权益以服务端订单/权益状态为准，不信任本地标记 |
| 单一 AI 入口 | 全站对话只在「AI 助手」；其他模块只做单次生成，不另起对话 |

## 3. 产品架构

### 3.1 页面结构（5 Tab + 二级页，具体路由见 `src/app.config.ts`）

```
Tab 1 晨报 ── 今日时间线、情报、快捷入口（🧳 旅行、搜索）
Tab 2 收件箱 ─ 粘贴/截图 → 提取 → 草稿确认；工作助手
Tab 3 资料库 ── 热点聚合、AI 精选、收藏、最近浏览
Tab 4 日历 ─── 月视图、单日详情、快速添加、导出/同步
Tab 5 我的 ─── 身份、用量、会员、偏好、数据管理、注销

入口页：login（根路径先到登录页，已登录则跳转）

二级页（navigateTo，均在 main）：
  assistant（唯一 AI 对话）、search、membership、prefs、report
  shopping（购物清单）、ledger（记账）、sxm（省心买）、trade（行情）
  learn / learnDetail / learnCommunity
  questionBank / Answer / Mistakes / Import、papers、mockExam、mockExamResult
  sport、notify
  —— 以下仅存在于功能分支，main 无此路由 ——
  aiClass、aiGrade、learnSubject、learnLanguage（31 路由分支）；travel（feat/travel-spec）
```

桌面端（≥600px）用自绘左侧导航，移动端用 TabBar；两者入口集合一致。

### 3.2 数据与通道

```
用户数据：Taro storage（{data:值} 信封）
        ↕ 云同步（44 个 key，per-key 时间戳，冲突让用户裁决）
云端：WorkBuddy 云服务
        · auth：邮箱验证码 + 强制绑定手机
        · db：user_kv（RLS owner_id = auth.uid）、orders
        · storage：users/<uid>/…
AI：cloud.llm 直连（首选）→ 本地代理（开发）→ 明确降级
资讯：同源 /api/hotspot.json（构建烘焙）→ 跨域实时源 → 本地快照
天气：Open-Meteo（免费，无需 key）
```

## 12. 已知问题（不藏）

1. **发布路径单点**：`D:\Agent\dist` 已绑到错误的 app，正确入口目录是 `dist-restore`；误发会换域名并导致登录 403。
2. **门禁目录需分两张表**：已接入 CI 的与孤儿脚本分开统计，否则覆盖率系统性偏高。
3. **`a11y B-2e` 已改为不依赖外部图源**：允许「显式降级占位」，同时新增 B-2f 禁止「浏览器已放弃但仍留在 DOM 的破图」；此前因 billboard URL 404 / ifanr TLS 失败误红。
4. **命中区未全覆盖**：375 视口仍有约 54% 可点元素 <44px，窄屏更差；门禁只静态读 scss，锁实现不锁事实。
5. **多个模块未并入 main**：`aiClass`、`aiGrade`（功能分支 31 路由）与 `travel`（`feat/travel-spec`）都不在 main；线上构建来自旧分支，与 main 不等价。
6. **规模数字有分支口径**：main 为 27 路由 / 44 键 / 1505 词典键；发布分支为 27 / 43 / 1563；工作分支为 31 / 45 / 1748。引用时必须带口径。
7. **命中区 54%**：来自外部审计的浏览器实测，本仓库门禁未纳入该口径，未在本轮复核。
8. **`AGENTS.md` 计数漂移**：曾写 18 个同步键（实际 44）；修复在 `release/consolidated`，随本 PR 合入 main 后 main 才是 44。
9. **「主动送达」未兑现**：H5 无推送；ICS 订阅方案已被 `icsExport` 的隐私约束否掉，v3.3 改走邮件/小程序订阅消息。
10. **AI 回答无可点引用**：情报有条目来源，但助手回答本身不附引用；与 Perplexity/NotebookLM 的信任基线有差距。
11. **收件箱缺微信转发入口**：只能复制粘贴；微信生态内最自然的动作未接。
12. **晨报层不标当日冲突**：冲突检测只在提取时触发，晨报看到的是已排好的日程。
13. **云端记账幂等未证实**：`llm_events` 无请求 ID、无对账；超时重发是否双记账无证据（F52 本地侧正确）。
14. **门禁覆盖率被高估**：151 个非变异脚本中约 54 个无 npm script / 不在 CI / 不在 `verify-all`；其中部分启动即崩（缺 `bundle:true`、桩缺导出），"74/75" 不包含它们。
15. **死同步键已清理**：`briefingChatLog` 全仓零读写，已从 `SYNC_KEYS` 删除（分支 44 → 43）；main 合并后同步为 43。

### A2　工作日：把群聊变成日程

1. 复制群消息 → 收件箱粘贴 → 提取。
