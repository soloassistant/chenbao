# H5 支付开通：照做清单

> 只留可执行动作。想了解「为什么这么设计」看 `docs/H5支付权益闭环-执行手册.md`。
> 全程约 20 分钟，其中 SQL 一步必须在数据库控制台（service role）做。

## 1. 数据库（一次性，约 3 分钟）

在 WorkBuddy 应用数据库控制台执行：

```sql
-- ① 整份执行这个文件的内容
--    .tools/sql/v9-h5-paid-orders.sql

-- ② 插密钥（随机生成，别用示例值）
INSERT INTO public.app_secrets (name, value)
VALUES ('pay_gateway_hmac', encode(gen_random_bytes(32), 'hex'))
ON CONFLICT (name) DO NOTHING;

-- ③ 取出来，第 2 步要用（只在这里看，别贴文档/群里）
SELECT value FROM public.app_secrets WHERE name = 'pay_gateway_hmac';
```

**自检（5 条，全部要过）：**

```sql
-- A) 函数存在且 SECURITY DEFINER → 期望 1 行，prosecdef = t
SELECT proname, pronargs, prosecdef FROM pg_proc WHERE proname = 'redeem_paid_order';

-- B) 只有 authenticated 能执行 → 期望只出现 authenticated / EXECUTE
SELECT grantee, privilege_type FROM information_schema.routine_privileges
 WHERE routine_name = 'redeem_paid_order';

-- C) 两张新表客户端零权限 → 期望 0 行
SELECT grantee, privilege_type FROM information_schema.role_table_grants
 WHERE table_name IN ('app_secrets','paid_order_claims')
   AND grantee IN ('PUBLIC','anon','authenticated');

-- D) 密钥长度 → 期望 64
SELECT name, length(value) FROM public.app_secrets;
```

## 2. 部署网关

```bash
export PORT=8080
export XUNHUPAY_APPID='<商户 appid>'
export XUNHUPAY_APPSECRET='<商户密钥>'
export PAY_GATEWAY_HMAC_SECRET='<第 1 步 ③ 那个 64 位串，必须逐字符相同>'
export PAY_NOTIFY_URL='https://<网关域名>/notify'
export PAY_RETURN_URL='https://<前端域名>/#/pages/membership/index'
export PAY_PUBLIC_BASE='https://<网关域名>'
export PAY_LEDGER_FILE='/var/lib/paygw/orders.json'   # 必须配，否则重启后签不出凭证
export PAY_CORS_ORIGIN='https://<前端域名>'            # 别留 *

node server/pay-gateway/index.mjs
```

**检查：**

```bash
curl -s https://<网关域名>/health
```

要看到 `"configured":true` 且 `"claimReady":true`。
`configured:false` = 商户参数没配；`claimReady:false` = HMAC 密钥没配或不足 32 位。

## 4. 上线前必验（5 条，别跳第 1 条）

1. **负路径（最重要）**：登录态下，随便造一个 sig 调函数，必须报「支付凭证验签失败」，且
   ```sql
   SELECT count(*) FROM public.orders WHERE channel = 'wechat_h5';   -- 期望 0
   SELECT count(*) FROM public.paid_order_claims;                    -- 期望 0
   ```
2. **金额篡改**：把凭证里的 `amount_cents` 改成 `690` 再调 → 必须报「金额与套餐不符」。
3. **换账号**：用 B 账号拿 A 的凭证核销 → 必须报「该支付凭证不属于当前账号」。
4. **重复核销**：同一凭证连调两次 → 第二次 `already=true`，`orders` 只多一行。
5. **真单小额**：早鸟月付 ¥6.9 走完整链路 → 回跳后提示成功、会员状态变已开通、
   「订阅记录」出现 `wechat_h5` 订单、到期日 = 付款日 + 1 个月。

## 5. 出问题查什么

```sql
-- 这笔订单走到哪一步了
SELECT * FROM public.paid_order_claims WHERE order_id = '<订单号>';
SELECT * FROM public.orders            WHERE order_id = '<订单号>';
```

| 现象 | 原因 | 处置 |
|---|---|---|
| 两表都无行 | 凭证没到服务端（网关没配 HMAC / 用户没回跳） | 让用户重开页面回跳；仍不行则核对支付平台流水后人工补（**必须同时写 `paid_order_claims`**，否则会补第二次） |
| 两表都有行，但用户看不到会员 | 当前登录账号 ≠ `owner_id` | 让用户用下单那个账号登录 |
| 报「凭证已过期」 | 超过 7 天 | 核对流水后人工补 |
